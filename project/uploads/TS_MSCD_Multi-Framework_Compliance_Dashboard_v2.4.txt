[Heading1] 1. Pendahuluan
Dokumen ini menerjemahkan PRD-MSCD-01 v2.0 menjadi spesifikasi yang dapat langsung diimplementasikan. Tiga ketentuan baru PRD — multi-framework, dua mode implementasi, dan repositori berkas milik pelanggan — masing-masing dijawab oleh satu komponen arsitektur: Framework Engine, Deployment Profile, dan Storage Abstraction Layer. Ketiganya wajib ada sejak MVP.
[Heading2] 1.1 Konvensi Umum
Konvensi
Ketentuan
Primary key
UUID v4 pada kolom id. ID bisnis (requirement_code, doc_id, risk_code) unik dalam lingkupnya tetapi bukan primary key.

[Heading2] 2.2 Topologi SaaS
[ListParagraph] Multi-tenant pada satu kluster per region. Isolasi: skema PostgreSQL per organisasi, Row-Level Security pada organization_id sebagai lapis kedua, dan kunci enkripsi data per tenant (envelope encryption dengan KMS).
[ListParagraph] Region dipilih per tenant saat onboarding dan tidak dapat dipindah tanpa migrasi terkelola. Seluruh data tenant, cadangan, dan log aplikasi yang memuat data tenant berada di region tersebut.
[ListParagraph] Kredensial konektor tenant dienkripsi dengan kunci tenant; operator penyedia tidak dapat membacanya dalam bentuk plaintext.
[ListParagraph] Pembaruan aplikasi bergulir (rolling) dengan migrasi skema yang kompatibel ke belakang satu versi.

[Heading2] 2.5 Lisensi dan Entitlement
Lisensi adalah dokumen JSON bertanda tangan (Ed25519) yang memuat: organisasi, masa berlaku, framework yang diizinkan, jumlah MS, jumlah pengguna, adapter penyimpanan, dan fitur. Aplikasi memverifikasi tanda tangan dengan kunci publik yang tertanam di image, sehingga validasi On-Premise tidak memerlukan koneksi. Lisensi kedaluwarsa memberi masa tenggang; setelahnya aplikasi masuk mode hanya-baca, tidak pernah menghapus atau mengunci data pelanggan.

[Heading2] 3.2 Siklus Hidup Pack
[ListParagraph] Validasi — tanda tangan, checksum dataset, kompatibilitas engine_min_version, dan integritas referensial (misalnya setiap finding_condition merujuk requirement yang ada).
[ListParagraph] Instalasi — dataset dimuat ke tabel referensi global dengan kunci (framework_version_id, kode). Instalasi bersifat atomik; gagal sebagian berarti rollback penuh.
[ListParagraph] Aktivasi — Tenant Administrator membuat ManagementSystem pada framework_version tersebut. Template (aktivitas, dokumen, pustaka yang dapat disunting) disalin ke ruang tenant; konten referensi tidak disalin.
[ListParagraph] Pembaruan minor — perbaikan konten pada edisi yang sama (misalnya kondisi temuan baru). Diterapkan otomatis ke konten referensi; salinan template di tenant ditawarkan sebagai pembaruan, tidak ditimpa.
[ListParagraph] Transisi edisi — pack edisi baru dipasang berdampingan. Lihat Bagian 3.4.

[Heading2] 3.4 Transisi Edisi
Pemetaan antar edisi disimpan di mappings/ dengan jenis relasi: equivalent, split, merged, changed, new, removed. Edition Transition Assistant menjalankan:
UNTUK SETIAP relasi r PADA ms (dokumen, bukti, applicability) YANG MERUJUK requirement lama q:
  m = mapping[q]
  JIKA m.type = equivalent MAKA salin relasi ke requirement baru, tandai auto_mapped
  JIKA m.type IN (split, merged, changed) MAKA buat transition_task untuk MS Manager
  JIKA m.type = removed MAKA arsipkan relasi, jangan hapus
UNTUK SETIAP requirement baru tanpa relasi masuk: buat transition_task (gap)
Selama transisi, MS memiliki dua baris management_system_version; audit trail mencatat edisi aktif pada setiap perubahan.
[Heading2] 3.5 Cakupan Business Rule per Framework
Setiap business rule memiliki atribut applies_to (daftar framework_code atau ALL) di rules.json. Engine hanya mengevaluasi rule yang aktif untuk MS entitas terkait. Untuk entitas bersama, rule dievaluasi untuk setiap MS yang tertaut, dan pelanggaran di salah satu MS cukup untuk menolak transisi.

[Heading2] 5.3 Alur Penyerahan Berkas
[Heading3] Pass-through
[ListParagraph] Browser mengunggah ke api; api meneruskan stream ke storage-gateway tanpa menulis ke disk (buffer memori terbatas, atau berkas sementara terenkripsi yang dihapus segera bila berkas besar).
[ListParagraph] storage-gateway menghitung SHA-256 sambil menulis ke repositori pelanggan melalui upload session.
[ListParagraph] Repositori mengembalikan item id dan version id; storage_object dibuat dengan hash_source = computed.
[ListParagraph] Berkas sementara dihapus dan penghapusan dicatat di log teknis.
[Heading3] Link
[ListParagraph] Browser membuka file picker repositori (OneDrive/SharePoint picker atau Google Picker) dengan token pengguna.
[ListParagraph] Browser mengirim item id terpilih ke api.
[ListParagraph] storage-gateway memanggil link: mengambil version id terkini, hash penyedia, dan metadata langsung dari repositori, lalu mematok versi.
[Heading3] Zero-transit
[ListParagraph] api menerbitkan upload intent bertenggat: folder tujuan, batas ukuran, dan kode korelasi.
[ListParagraph] Browser mengunggah langsung ke repositori dengan token delegasi pengguna (misalnya upload session Microsoft Graph atau resumable upload Google Drive).
[ListParagraph] Browser melaporkan item id dan kode korelasi ke api.
[ListParagraph] storage-gateway memverifikasi item di repositori (ada, di folder yang benar, dibuat setelah intent diterbitkan) dan mengambil hash penyedia. Metadata dari browser tidak dipercaya.
[ListParagraph] Bila repositori tidak menyediakan hash untuk jenis berkas tersebut, storage_object dibuat dengan hash_source = none dan integritas hanya berbasis version id; status ini ditampilkan kepada pengguna dan auditor.
[Heading2] 5.4 Konvensi Folder
{root}/{MS code}/{cycle}/{evidence|documents}/{requirement or item code}/{evidence_code}_{produced_at}.{ext}
Contoh: /Compliance/ISMS-JKT/2026-2029/evidence/A.8.13/EV-0412_2026-09-20.pdf
        /Compliance/_packs/ISMS-JKT/Stage2-2026/   ← salinan evidence pack

[Heading2] 5.5 Link Health Check
Job worker memeriksa storage_object secara berkala dengan prioritas: bukti yang menopang status implemented, bukti yang akan masuk evidence pack terjadwal, lalu sisanya. Frekuensi default harian untuk prioritas tinggi dan mingguan untuk lainnya; dibatasi rate limit per repositori.
hasil = adapter.stat(obj)
JIKA hasil.not_found MAKA status = &quot;missing&quot;
JIKA hasil.forbidden MAKA status = &quot;access_denied&quot;
JIKA hasil.item_id berubah folder MAKA status = &quot;moved&quot; (tetap sah, perbarui lokasi)
JIKA hasil.version_id &lt;&gt; obj.external_version_id:
    JIKA versi yang dipatok masih dapat diambil MAKA status = &quot;version_changed&quot;
    SELAIN ITU status = &quot;pinned_version_lost&quot;
JIKA obj.hash_source = &quot;provider&quot; DAN hash versi terpatok berbeda MAKA status = &quot;hash_mismatch&quot;
JIKA repositori tidak dapat dihubungi MAKA status tetap, tandai &quot;verification_pending&quot;
SELAIN ITU status = &quot;intact&quot;
[Heading2] 5.6 Evidence Pack pada Repositori Pelanggan
[ListParagraph] Worker menentukan daftar bukti sesuai lingkup paket (MS, klausul, kontrol, periode).
[ListParagraph] storage-gateway memastikan folder paket ada, lalu memanggil copy_within per berkas. Isi berkas tidak melewati aplikasi.
[ListParagraph] Worker menghasilkan manifest (PDF dan CSV) berisi evidence_code, requirement, produced_at, external_version_id, hash_algorithm, hash_value, link_status saat pembuatan, dan lokasi salinan.
[ListParagraph] Manifest disimpan di folder paket yang sama dan dicatat sebagai storage_object.
[ListParagraph] Bukti dengan link_status selain intact atau moved dicantumkan di bagian pengecualian manifest, tidak diam-diam dilewati.
[Heading2] 5.7 Mode Kegagalan
Kondisi
Perilaku Sistem
Repositori tidak dapat dihubungi
Data terstruktur tetap berfungsi. Penyerahan berkas baru ke repositori itu ditolak dengan pesan jelas; tidak ada fallback diam-diam ke Managed Vault. Status integritas memakai hasil terakhir dan ditandai verification_pending.
Kredensial dicabut atau kedaluwarsa
connection_status = revoked; notifikasi ke Tenant Administrator; bukti terkait tidak diturunkan statusnya sampai 72 jam berlalu, agar pencabutan sementara tidak memicu kaskade penurunan status.
Rate limit penyedia
Backoff eksponensial; link health check dijadwal ulang; tidak memengaruhi pengguna.
Adapter dinonaktifkan lisensi
Repositori menjadi hanya-baca bagi aplikasi; tautan lama tetap diverifikasi.

[Heading1] Disclaimer dan Kepemilikan
Spesifikasi ini menerjemahkan PRD-MSCD-01 v2.4 menjadi bentuk teknis. Nama tabel, tipe data, ambang nilai, ukuran infrastruktur, dan rujukan teknologi bersifat usulan dan perlu disesuaikan dengan pilihan teknologi serta konvensi rekayasa organisasi Anda.
