## Plan findings

- C.4 and C.6: `audit_trail.edition` and `audit_log.edition` are `varchar(40)`, but F.11 stores two editions during a transition as `<pack_id> <version>, <pack_id> <version>`. With the current packs `ISO37001-2016 1.10.0, ISO37001-2025 1.0.0` is 41 characters, and `pack_id varchar(40)` plus `pack_version varchar(20)` allow one edition of 61. Either widen both columns (for example `varchar(160)`, in a migration of the WP that next changes these tables) or define a compact two-edition format. Until then the writer cuts the value to 40 characters and logs a warning with the full edition.
- D.1: a streamed body (multipart, raw bytes) cannot be hashed before the handler reads it. The plan should say that such idempotent routes claim the key in the handler with a digest of the content (deviation 19).
- D.3 `GET /admin/audit-trail/verify`: the platform result reports `checked` and `firstBrokenSeq` of the installation-wide chain, so every organisation sees the installation's row count. The plan asks for both chains; if that count should stay hidden from tenants, the platform result could carry only whether the chain is broken and `anchorOk`. WP-05 may also add `rateLimits` (and 429) to `auditTrailVerifyRoute`, as on the export route; the server already contains the cost by reuse (deviation 20).
