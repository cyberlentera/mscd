Root enforcement. Every item an operation reads, links, lists, copies or verifies must lie below `config.rootFolderId`, and below the call's `scopeRoot` when one is given; a scope root must be the root folder or one of `config.roots` and must itself lie below the root folder. Microsoft 365 places items by `parentReference.path` (compared without regard to case, as SharePoint names are) and walks parent ids when Graph sends no path; an item of another drive is refused. Google Drive walks parent folders by id up to the drive root (one request per level, cached within a call; the root folder and the call's system folder, read first, are in that cache, so no folder is read twice in one call) and refuses items of another drive. Ids are checked against the D.5 patterns (and folder paths, file names and revision ids against their rules) before any request; path segments pass through `encodeURIComponent`, queries through `URLSearchParams`, names in Drive queries through Drive's quoting.

Error mapping (both adapters): token endpoint refusals and 401 answers are `unreachable` with `credentialInvalid` (`stat` answers `{outcome: 'unreachable', detail: 'credential_invalid'}`, `test-connection` answers `revoked`); 403 is `forbidden`; 404 is `not-found`; 429, 503 and Google's 403 rate limit reasons are `rate-limited` with `Retry-After`; 413 is `too-large`; other 4xx `bad-request`; other 5xx and network failures `unreachable`.

## Plan findings

- D.2 `GoogleDriveRepositoryConfig` requires `driveId`, but a My Drive has no drive id in the Drive API. The adapter recognises a My Drive by a root folder without `driveId` and then does not use `config.driveId`; the api may want a separate field or rule for My Drive repositories.
- `StatResult` has no detail for an item moved outside the root or trashed (deviation 4); a `detail` value such as `outside_root` or `trashed` would let WP-23 show the reason.
- `PutInput.contentLength` is optional, but Microsoft 365 upload sessions need the total size (deviation 6). D.5 could require `Content-Length` on `PUT /v1/objects` for pass-through repositories.
- I.1 has no profile key for an outbound proxy; the adapters follow the standard environment variables (deviation 18).
