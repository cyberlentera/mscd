# WP-36 handoff: risk and context registers

## What was built

| Area | Files | Content |
|---|---|---|
| Registers | `apps/server/src/modules/risk-registers/registers.service.ts` | `GET /ms/{ms}/registers/{register}`: rows of context issues, interested parties, assets, risks and metrics linked to the system (`entity_ms_link`), with `q` (code, title, owner name), `owner`, `status` (`open` or `ready` from `pending_action` for the chain kinds) and paging, filtered by `ScopePolicy` (owner scoping for Domain Owners, Risk Owners and Compliance Investigators; nothing for external auditors). `POST`: register fields of the kind only (a field of another kind or a read-only field is 400), lookups of the system's edition (risk profile from `ref.risk_profile`, the edition's only profile by default; likelihood, consequence and residual values inside the profile scales; impact dimensions of the profile; `treatment_option` from `ref.lookup_value`; `asset_type` checked only when the pack defines the domain; metric frequency from `ref.evidence_frequency_rule`), BR-17 for risks, `linkedMs` (the path system must be listed, the first is primary, `integrated_mode` for more than one), 409 for a live code, `entity_ms_link` rows, `register.created`. `PATCH`: `If-Match`, changed fields only, code changes checked for duplicates, `linkedMs` replaced with the primary moved first (A-29), BR-17 when the owner is set to none, BR-22 confirmation for rows shared by several systems, `register.updated`. `POST /ms/{ms}/metrics/{id}/values`: overlapping periods are 422, `last_measured_at` keeps the latest period end, the metric's pending action is completed, `metric.value_recorded` |
| Treatments | `treatments.service.ts` | `POST /ms/{ms}/risks/{id}/treatments` (`riskCode` must match the path risk; target in the active edition, else 422; 409 duplicate code per system; status `proposed`; `record_reference` rows treatment up to the risk and down to the target, risk down to the treatment), `PATCH /ms/{ms}/treatments/{id}` (`If-Match`; title, owner, target, target date), `POST .../transitions` through the C.13 rows (`pickTransition`: full grant, or the own grant of `risk.treatment.update` on the caller's own treatment; closing without residual acceptance is 422 BR-04 from the machine's rejection rows; `residual_accepted` is 409 on this route), `implemented_by_user_id` and `implemented_at` on implementation, `closed_at` on closure, `risk.treatment_transition` |
| Residual acceptance | `treatments.service.ts` | `POST /ms/{ms}/risks/{id}/residual-acceptance`: only the risk's `owner_user_id` (403 otherwise, whatever the role); the named treatment of the risk in the system, or its only implemented one (400 when there are several, 422 BR-04 when none); 422 BR-04 when the treatment is not `implemented` or the caller implemented it (`@BusinessRule('BR-04')`); a `residual_acceptance` row with the implementer snapshot (`implemented_by_user_id`, whose CHECK constraint refuses the implementer at the database), the residual score (likelihood times consequence), the treatment moved to `residual_accepted`, the risk's residual values and `residual_accepted_at`; `risk.residual_accepted` and `risk.treatment_transition`; 201 |
| Evidence | `evidence.service.ts` | `POST /ms/{ms}/evidence` (owner, frequency of the edition, at least one target that has an applicability entry in the path system, else 422; 409 duplicate code; primary link to the path system; `evidence_target` rows; `freshness.recompute` with the evidence and entries), `PATCH` (`If-Match`, BR-22 for evidence that serves several systems, `freshness.recompute` per system it serves), `POST .../targets` (target system from the body, `integrated_mode` when it differs from the path system, 409 for a duplicate target, 422 for an entry the system does not have, a non-primary link to the target system, BR-23 warning through the engine, `freshness.recompute` for the target system), `POST .../targets/{targetId}/remove` (never the last target, the link of a system the evidence no longer serves is removed unless primary) |
| Entity links | `entity-links.service.ts` | `POST /ms/{ms}/entity-links` (record by its business code: `code`, `doc_code` or `evidence_code`; 404 unknown, 409 already linked, `integrated_mode`, optional primary), `make-primary` (unset the old primary first, then set the new one; a message when it already is), `remove` (422 for the primary link; 422 for evidence that still targets entries of that system). A link id resolves only when its record is linked to the path system (404 otherwise) |
| Operating criteria | `operating-criteria.service.ts` | `PUT /ms/{ms}/applicability/{id}/operating-criteria`: frequency of the edition (422 otherwise), description, upsert of the live `operating_criteria` row, new entry ETag, `applicability.updated`, `freshness.recompute` for the entry; the same values again change nothing (`changed: []`) |
| Rules | `rules.ts` | `@BusinessRule` providers BR-04 (error), BR-17 (error), BR-23 (warning, the WP-21 query over `ref.requirement_mapping.evidence_reusable = false` in either direction); `confirmShared` for BR-22 (409 `confirmation-required`, `affected` the other systems' slugs, the message names their codes), active when any linked system's edition activates BR-22 |
| Shared steps | `support.ts` | `pickTransition`, `grantedInFull`, `refOf` (module `audit` for register rows and treatments, `surveillance` for evidence, `implementation` for entries, as the read model names them), `commandResult` (sorted `changed`), `bump` (the `updated_at` that changes the ETag), `linksOf`, `editionOf`, `assertFrequency`, `targetOf`, `enqueueFreshness` (`fr:<org>:<ms>`, 5 seconds, 3 retries), `duplicateCode` |
| Routes and module | `risk-registers.controller.ts`, `risk-registers.module.ts`, `index.ts`, `README.md` | The 15 routes of `packages/shared/src/api/risk-registers.ts` and the operating criteria route of `packages/shared/src/api/implementation.ts` through `@ApiRoute`; both contract files needed no change |

Chain records stay meaningful for the read model (C.10): a new risk waits for a treatment ("Select a treatment: no treatment linked", the sample's text), cleared by its first treatment; a new metric waits for its first value; a treatment carries "Approve the treatment", "Start the implementation", "Report implementation progress" (with "the target date has passed" when delayed), and nothing once implemented, accepted or closed; an implemented treatment gives the risk "Residual risk acceptance by Risk Owner" (held by the risk's owner), cleared by the acceptance when no other implemented treatment of the risk waits. Completing an action writes `action_completed_at` and `action_completed_by`.

Audit entries use the F.11 actions `register.created`, `register.updated`, `risk.treatment_transition`, `risk.residual_accepted`, `metric.value_recorded`, `evidence.created`, `evidence.updated`, `evidence.target_added`, `evidence.target_removed`, `entity_link.created`, `entity_link.removed` and `applicability.updated`. A register row's business code is written as `register_code` (and a treatment's as `treatment_code`), because F.11 redaction treats a key named `code` as a secret.

## Deviations and decisions

| # | Item | Plan | Built | Reason |
|---|---|---|---|---|
| 1 | BR-22 registration | "Rules registered here: BR-22 (register edits)"; WP-35 also registers BR-22 | WP-35 registers the BR-22 provider; WP-36 calls `confirmShared`, which asks `RuleEngine.isActive` and answers 409 itself | `RuleEngine` refuses two providers of one rule; WP-35's `SharedChangeGuard` notes the same split |
| 2 | Residual acceptance permission | `risk.residual.accept` (own) | Always the risk's `owner_user_id`, for every role (the matrix grants it own-scoped to MM, PO, DO and RO) | F.6 |
| 3 | Treatment for acceptance | `treatmentId?` | Named treatment, else the risk's only implemented treatment in the system; several implemented treatments without a name is 400 | The request needs one treatment to move |
| 4 | Register create permission for own grants | "own: the new record's owner must be the session user" | Without `ownerHandle` the caller becomes the owner (risks excepted: they need `risk.manage` in full, so a Risk Owner cannot create risks) | F.6 `risk.manage` own covers only the assessment fields of own risks |
| 5 | Risk Owner assessment fields | Not listed | `likelihood`, `consequence`, `impactDimensions`, `residualLikelihood`, `residualConsequence`, `treatmentOption`, `assessedAt`, `nextReviewAt` | Exported as `RISK_ASSESSMENT_KEYS` |
| 6 | Read-only register fields | Part of `RegisterCreate` and `RegisterPatch` | `residualAcceptedAt` (set by residual acceptance) and `lastMeasuredAt` (set by metric values) are 400 in a request | Each has its own command |
| 7 | `linkedMs` | First is primary | Must include the path system (422 otherwise); an unknown system is 404 | A row created or kept through a system's route stays visible there |
| 8 | Asset type lookup | Lookups validated against `ref.lookup_value` | `treatment_option` always; `asset_type` only when the edition defines that domain (no pack defines it yet) | Asset types are free text until a pack lists them |
| 9 | Entity links by code | Every shareable type | `audit_event` is 422 (it has no business code) | `EntityLinkRequest` names records by code |
| 10 | Metric pending action | Not stated | A new metric waits for its first value; recording any value completes the metric's pending action | Keeps the chain record meaningful (C.10) |
| 11 | Register list `status` | `status` query | `open` or `ready` for chain kinds (from `pending_action`); interested parties and assets have none | The tables have no status column |
| 12 | Target system rights | Not stated | Adding a target in another system needs `evidence.manage` in the path system and `integrated_mode`; the target system must exist in the organisation | The route is ms-scoped on the path system |

## Follow-ups

- WP-35: `records.service.ts` treats BR-17 on assignment as a warning through `RuleEngine.isActive`; keep it that way, because the BR-17 provider registered here has severity `error` (an `enforce` call would answer 422).
- WP-25 and later UI work: register forms send `If-Match` with `ref.etag` from the list or the last `CommandResult`; residual acceptance returns the risk ref in `ref` and the treatment ref in `data.treatment`; target creation returns `data.targetId`; entity link creation returns `data.linkId`.
- WP-30: the RBAC and contract suites can reuse `test/int/risk-registers/helpers.ts` (`createRiskApp` includes WP-35's record commands and the freshness service).
- WP-37: `confirmShared` (BR-22) is exported from `src/modules/risk-registers` for the management review edits; `SharedChangeGuard` of WP-35 does the same with the engine's BR-22 provider.
