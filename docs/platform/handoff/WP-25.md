# WP-25 handoff: web API data source and controller

## What was built

The API build of the web app (`VITE_DATA_SOURCE=api`) now opens the application after sign-in instead of the panel "MSCD could not start": every screen reads the api, and every action that changed data in the sample is a command of the api. The sample build is unchanged (same 262 E2E tests, no API code in its bundle), and the API bundle holds no sample records.

|---|---|

Command mapping (H.4), all through the shared paths:

| Method | Request |
|---|---|
| `markComplete`, `verify` | `POST /ms/{ms}/applicability/{ref.id}/transitions` (`req`) or `/activities/{ref.id}/transitions` (`act`) with `{to: 'complete'}`, `{to: 'implemented'}` or `{to: 'verified'}`; a target that does not fit the kind answers 422 without a request |
| `assign` | `POST /ms/{ms}/records/{ref.entityType}/{ref.id}/assignment {kind, holder, dueAt}` with `If-Match: ref.etag`, for every kind of RecordKey (`req`, `soa`, `doc`, `ev`, `act`, `x`, `prep`, `cycle`, `drift`) |
| `remind`, `remindAll` | `POST /reminders {ms, ref: {module, entityType, id, code}, recipient}` (or `{ms, recordKey, recipient}` when the snapshot has no ref for the key); `POST /reminders/bulk {ms, scope: 'open_chain_items'}` |
| `completeRecordAction` | `task`: `POST /tasks/{id}/complete {}`; `x` and `drift`: `POST /ms/{ms}/records/{entityType}/{id}/complete-action {}`; `soa` and other kinds: 422 without a request |
| `startReview`, `recordBlocker` | `POST /ms/{ms}/documents/{id}/transitions {to: 'in_review'}`; `POST /ms/{ms}/activities/{id}/transitions {to: 'blocked', blockerGateItemRef, blockerReason}` (not called by the controller, Appendix 1) |
| `listPickerFiles` | `GET /storage/repositories/{ms.loc}/browse?ms=&kind=&recordId=&path=` with the current quarter's folder (`Evidence/<year>/Q<n>`) or `Documents`, then the system root when that folder answers 404 (deviation 3) |
| `linkFile` | evidence: `POST /ms/{ms}/evidence/{id}/files {source: 'link', repository, externalItemId, producedAt: today, mode}` with `relink` when the pinned file is unverifiable; document: `POST /ms/{ms}/documents/{id}/versions {source: 'link', repository, externalItemId}` |
| `uploadFile` | `POST /storage/upload-intents {ms, kind, recordId, fileName, size}`, `PUT` of the file to `contentUrl` (`application/octet-stream`, with upload progress through XMLHttpRequest in the browser), then the evidence file or document version with `source: 'upload'` and `uploadIntentId`. An intent without `contentUrl` (zero-transit) answers 422 "Link the file instead" |
| `repositoryAction(repoId, action, msId?)` | By `REPOS[].ref`: `test` `POST /admin/storage/repositories/{ref}/test`; `reauthorise` `.../reauthorize`, then `navigate(redirectUrl)`; `moveToLibrary` `.../move-requests {ms}` |
| `pageAction(ms, action, arg?)` | `exportBoard` and `exportReadiness`: `POST /exports`, then `GET /exports/{taskId}` up to 20 times every 1.5 s; the download opens when the task succeeded, else the result says the export is queued. `exportSoa`, `exportDocs`: open the GET export URLs (`format=xlsx`). `evidencePack`: `POST /ms/{ms}/evidence-packs {}`. `auditorAccess`: `POST /ms/{ms}/auditor-access {email: arg}`. `runCheck`: `POST /ms/{ms}/link-health/run`. `calendarFeed`: `POST /ms/{ms}/calendar-feed`. `checkUpdates`: `POST /admin/packs/check-updates`. `importBundle`: multipart `bundle` to `POST /admin/packs/import`. `verifyPhase`: `POST /ms/{ms}/phases/{arg}/verify` |

Controller changes (`MscdApp.jsx`), API mode only unless stated:

- Step 5: `applySnap` and `apiState` after the first load, every command reload, the organisation switch and the persona switch: `state.org = me.org.slug`; `state.ms` stays when the organisation's `orgs` entry lists it, else the first; `state.role = me.uiRoleByMs[ms]`. `setMs` and `go(..., {ms})` set the role of the new system, and `setMs` falls back to the role's first screen when the role cannot open the current one. `me` is `Me.user.handle`; `personOf` gives the session user's name when `PEOPLE` lacks it; `roleLabel` falls back to the static labels. The persona menu lists the demo personas in demo mode, otherwise the current role, and in API mode always ends with "Sign out" (`ds.logout()`).
- Step 6: `canVerify` reads `applicability.verify` (controls) and `activity.verify` (activities), `canSeePeople` reads `audit.pending.all`, from `permissions.ms[ms]`.
- Step 7: `openPicker` awaits `listPickerFiles` (busy bar meanwhile) and opens the picker with `modal.listing`; a failure shows the api message.
- Step 8: a hidden `<input type="file">` next to `AppView`; Upload in the vault modal opens its dialog and the chosen file goes to `uploadFile`. The same input imports a signed bundle on the on-premise Framework library.
- Step 9: commands queue behind each other (`_q`); while one runs, a fixed 3 px bar (`role="progressbar"`, accent colour of the theme, width from upload progress when known) sits above `AppView`. Before the first snapshot the loading panel; a failed load shows the api message with Try again and Sign out; a user without a system in the organisation sees a notice with Sign out.
- Step 10: `result.error` shows `li(error.message)`; warnings are appended to the success toast (`<toast>. <warning>`); a rejected promise shows the api message or "Connection lost. Try again."; an organisation switch refused with `reauth-required` shows no toast (the boot router shows the sign-in page).
- Step 12: without `PACKS[ms]` the pack card shows `-`; without `LICENCE` every licence field shows `-` and the feature list is empty (also in sample mode, where both are always present).
- Step 13: My Tasks adds the stored tasks of `GET /tasks` (kind `task`; title the task title, button Done, `completeRecordAction`); a `soa` item opens the gate item like a gated control.
- Step 14 and the commands of WP-07's follow-up: Remind (requirement, document, evidence, chain item, activity, drift row), Remind all holders, Run integrity check, the export, evidence pack, auditor access, calendar feed, check updates, import bundle and phase verification buttons, and the storage card actions call the source; toasts use `result.count` and `result.message` when present. The interface language goes to `Accept-Language` (`setLang`).

## Deviations

| # | Item | Plan | Built | Reason |
|---|---|---|---|---|
| 1 | Reload after a command | H.4: the source calls `reload(snapshot, result.changed)` | The controller calls `ds.reload` after a successful command (WP-07's `command()`), then shows the toast | Commands answer `CommandResult` (UI 4.2), not a snapshot; one place reloads for both sources, and the toast still follows the reload |
| 2 | `createDataSource()` without options in API mode | H.1: loads the API source | Rejects with "VITE_DATA_SOURCE=api is not available without the boot router's ApiClient (options.client)"; with `{client, me, profile}` (the boot router) it loads the API source | A source with a client of its own would hide session ends, `reauth-required` and sign-outs from the boot router. The message also keeps the WP-07 unit test `createDataSource loads the sample source unless the build selects the API source` passing (its last line expects a rejection matching `VITE_DATA_SOURCE=api is not available`; see Follow-ups) |
| 3 | Picker folder | `browse?ms=&kind=&recordId=` | Adds `path`: `Evidence/<year>/Q<quarter of today>` for evidence, `Documents` for documents (the folders WP-21 uploads to), and the system root when that folder answers 404 | `browse` lists the files of one folder; the root of a system holds only folders, so the picker was empty in a live run. The demo picker files are in `Compliance / ISMS / Evidence / 2026 / Q3` |
| 4 | Persona menu | Sign out outside demo mode | Sign out in every API session, also with demo personas | A demo user could otherwise not sign out |
| 5 | Auditor guest access | `POST /ms/{ms}/auditor-access` | The address is asked with the browser's prompt dialog (cancel sends nothing); the request has no `expiresInDays` (server default 14) | No form exists in the generated views (R-04); the toast text stays as the plan says |
| 6 | Document version toasts | Sample texts "v<n> approved" | API mode: "<code>: <file> linked, new version in review" and "<code>: <file> uploaded, new version in review" | The api puts a new version `in_review` (A.4 5.7); the sample approves it |
| 7 | Exports | Not specified how the file arrives | `exportBoard` and `exportReadiness` poll the task for 30 s and open the download; after that the toast says the export is queued (the `export_ready` notification, WP-24, carries the link) | WP-24 follow-up |
| 8 | Busy bar colour | "3 px progress bar" | Fixed colours `#ad4f0b` (light) and `#e8731a` (dark), the theme's `--acc` values, because the bar sits outside the `.mscd` element that defines the tokens | A second `.mscd` element would change `.mscd` selectors of the API E2E suite |
| 9 | `repositoryAction` | `(repoId, action)` | Optional third argument `msId` for `moveToLibrary` (the selected system when it uses the repository, else the first system that does) | `MoveRequest.ms` is required |
| 10 | Snapshot keys | UI 4.2 keys plus `me`, `permissions` | Also `refs`, `tasks` (stored tasks only), `systems`, `demo` | The controller needs the stored tasks and demo mode; `refs` drive every command |
| 11 | Type import of `static.js` | | `wire.ts` imports `LOC_VISUALS` from `static.js` under `@ts-expect-error` | The web tsconfig has no `allowJs` and `static.js` (WP-07) has no declarations |
