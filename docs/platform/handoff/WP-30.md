# WP-30 handoff: security, RBAC and contract test suite

## What was built

All suites run on the full api application of run mode `api` (`ApiModule`, `createHttpApplication`) on a copy of the demo template, with users that hold exactly one role of F.6 and sessions written through `SessionService`. The shared harness is `apps/server/test/int/contract/harness.ts`: `createFullApp`, fixture users per role, `sessionFor` and `demoSession`, request inputs built from the hand-written schema examples of the route table (`exampleInput`), and `callRoute`, which checks every answer against its `RouteDef` (declared status codes, the response schema, `Problem` for errors, the F.13 headers on file routes).

| File | What it proves |
|---|---|
| `contract/routes.test.ts` | J.3: every `RouteDef` is mounted with its method and path and nothing else under `/api/v1` (the storage gateway likewise under `/v1`); an unknown `/api/` path is 404; test-only routes stay unreachable unless the profile enables them; the OpenAPI document lists every route except the test-only ones; snapshot of route ids and methods in `contract/__snapshots__` |
| `rbac/expectations.ts`, `rbac/matrix.test.ts` | Generated from the F.6 matrix (`PERMISSION_MATRIX`) and the route table: every signed-in route called by a user of every F.6 role; the guard must deny (403, counted by `mscd_authz_denied_total`) or admit exactly as the matrix says; routes with `permissionBy` once per case; every answer also passes the contract checks |
| `rbac/own.test.ts` | Every "own" grant outside the transition tables: once with an own record (admitted), once with someone else's (403; file routes 404 through `canReadObject`) |
| `rbac/transitions.test.ts` | Every C.13 transition row performed by a person: an allowed role (not 403 or 409) and a disallowed one (403); own rows on own and foreign records; system-only rows 409; the C.13 rejections 422 with their rule; dedicated routes (residual acceptance, document versions, management system status, `ms.transition`, role grant approval, creation rows) |
| `rbac/auditors.test.ts` | The guest auditor is 403 on every non-GET business route with `authz.denied`, and 403 on `GET /admin/audit-trail/verify` and `/anchors` (follow-up 5); one `auditor.read` entry per request with the route id and the record refs; reads stop after `valid_until` and after revocation; Top Management is 403 on the storage object routes; `authz.denied` at most once per user, route and minute |
| `security/isolation.test.ts` | A `tst` session gets 404 for every route naming a system only `ndt` has and for every `ndt` record, also through `isms` (both organisations have it); slugs resolve in the session organisation; `/admin/users`, `/admin/identity-providers`, `GET /license`, `/admin/audit-trail` and `/admin/storage/*` of a Tenant Admin of both organisations show the signed-in organisation only; idempotency keys do not replay across organisations |
| `security/cross-system.test.ts`, `security/record-tables.ts` | Every route with `{ms}` and `{id}`: a record of another system of the same organisation is 404 for the manager of both; every `{entityType}` route likewise; an entity type outside `RECORD_ENTITY_TYPES` is 404; `POST /reminders` with a record of another system is 404 |
| `security/owner-scope.test.ts` | On every `GET` route: an ISMS Domain Owner who owns nothing sees no record and no holder of anyone, and is 403 on every route of QMS and ABMS; `/ui/org` and the other organisation reads carry no QMS record code; a `restricted` document is visible to its owner and the managers only; the guest auditor gets the G.5 projection on every route (no holders outside the system card, no `web_url`, evidence only from ready packs); Top Management gets pending data as aggregates only in `GET /ui/ms/{ms}` (follow-up 1) |
| `security/http.test.ts` | CSRF missing or wrong is 403 `csrf`; account lockout after 10 wrong passwords (the correct password then gets the generic 401); a planted cookie is never adopted and the session id changes after the password and after the second factor, the pre-MFA cookie is dead; a replayed TOTP code and an earlier step are refused; `Cache-Control: no-store`, the F.12 CSP and the other headers on success and error answers, no CORS header; a spoofed `X-Forwarded-For` changes neither the rate-limit keys nor the audited `source_ip`; an invalid `X-Request-Id` is replaced by a UUID; licence read-only mode blocks writes but not reads, and the licence upload ends it; with log level `info`, the log lines of guest start, password reset, the calendar feed, the OIDC callback and start, SAML start and a signed-in write carry no token, code, state, invitation, RelayState, cookie or CSRF value (read from the ring buffer that feeds the diagnostics archive) |
| `security/files.test.ts` | `text/html` and `image/svg+xml` evidence uploaded to the Managed Vault (SeaweedFS, gateway, mock providers) comes back as `application/octet-stream`, `attachment`, `default-src 'none'; sandbox`, also with `inline=true`; a Google Drive link pins the revision after `/v1/link` while another connection can lock the evidence row at once (no lock held across the call), and a failed pin answers BR-29 with nothing recorded (follow-up 3) |
| `security/identity.test.ts` | A session signed in through a provider of `tst` gets 409 `reauth-required` on `PUT /me/org` to `ndt` and keeps working in `tst`, a local session may switch; a local session cannot switch into an organisation with `local_login = 'disabled'`; an OIDC sign-in that ends at the local TOTP step audits `auth.login` with provider, subject and `amr` (follow-up 2); an invitation is redeemed once and a second use changes nothing; a guest access link works once, and after revocation neither a fresh link nor a returning guest's code request creates a code transaction |

The OIDC and SAML cases that need a real identity provider (invitations only through the inviting organisation's providers, a provider of organisation A refused for organisation B, ACS without the binding cookie, replayed assertions, `amr: ['otp']`) stay in `test/int/sso` (WP-16, WP-19) and pass with `MSCD_TEST_SSO=1`.

## Fixes made (each kept with its failing test as a regression test)

| # | Defect | Fix | Regression test |
|---|---|---|---|
| 1 | Top Management saw holders and due dates of other people's pending work in `GET /ui/ms/{ms}` (F.7, Q-8) | `ScopePolicyService.projectSnapshot` has a `top_management` branch: chain items, gate items, `X` records, `PREP`, `CYCLE_ITEMS` and `DRIFT` rows keep holder and date only when the caller holds them, otherwise holder `none` and no date; counts stay those of the full data (the `holderShown` rule of the per-screen endpoints) | `owner-scope.test.ts` |
| 2 | `auth.login` of an OIDC or SAML sign-in that finishes at the local TOTP step lacked the IdP subject | `MfaService.activate` adds `provider`, `subject` (the identity of that provider the callback stamped last) and `amr` | `identity.test.ts` |
| 3 | Google Drive `/v1/pin-version` inside the tenant transaction with row locks | Already moved before the transaction by WP-21 (handoff deviation 13): a failed pin fails the request before anything is written, a pin whose recording then fails leaves only a kept revision. No code change; the test proves both | `files.test.ts` |
| 4 | `POST /ms/{ms}/phases/{n}/verify` answered "Phase n verified" for a phase seeded as verified (WP-27 follow-up 2) | `ActivityService.verifyPhase` decides by the newest audit entry about the phase or its activities (by `seq`): only an activity change newer than the last confirmation writes `phase.verified`; otherwise "Phase n is already verified" with nothing changed | `commands-implementation/activities.test.ts`, `parity.test.ts`; `apps/web/e2e/phases.spec.js` runs the already-verified test in both projects (the `test.fixme` for the API project is gone; the BR-12 refusal was already in the shared test) |
| 5 | External auditors on `audit-trail.verify` and `audit-trail.anchors` | Holds: both routes name no system, so the guard refuses the guest (F.7) | `rbac/auditors.test.ts` |
| 6 | An `{entityType}` outside `RECORD_ENTITY_TYPES` answered 400 | `validateRouteInput` answers 404 before validation (D.1) | `cross-system.test.ts` |
| 7 | Create routes answered 404 (a record or system named in the body that does not exist) without declaring it | `errors` of `audit-events.create`, `findings.create`, `documents.create`, `applicability.create`, `registers.create`, `evidence.create`, `management-reviews.create` and `upload-intents.create` include 404 | `rbac/matrix.test.ts` (contract check of every answer) |
| 8 | `GET /ui/org` named QMS record codes to an ISMS-only reader through `MS[].gtSuggestions` | `filterOrgSnapshot` drops `gtSuggestions` from the cards of systems where the caller holds no role | `owner-scope.test.ts` |
