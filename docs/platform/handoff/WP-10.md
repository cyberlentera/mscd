# WP-10 handoff: mock provider servers

## What was built

`tools/mock-providers` is a Fastify application that stands in for the Microsoft identity platform token endpoint, the Microsoft Graph drive item API and the Google OAuth 2.0 and Drive v3 APIs, with the endpoints, shapes, admin API, id validation and fault switches of J.7 and every adapter call listed in D.5. State lives in memory. `tools/mock-providers/README.md` documents the endpoints, the admin API, the fault switches and the fixture format.

| Area | Files | Content |
|---|---|---|
| Application | `src/app.ts` | `buildMockProviders(options)` and `startMockProviders({port, host, fixtures, publicUrl, settings, onRequestLog})`; one catch-all body parser (every body arrives as bytes, so uploads keep their exact content whatever the Content-Type); request hook for latency and throttling; request log; errors mapped to the envelope of each API; unknown routes answered in that envelope |
| Identity | `src/identity.ts` | `POST /{tenant}/oauth2/v2.0/token` (client credentials with an RS256 or PS256 certificate assertion: `x5t#S256` or `x5t` must name a registered certificate within its validity, iss = sub = client id, `aud` the token URL, `exp` and `jti` required, five minutes of skew); `POST /token` (service account JWT bearer with `kid`, audience, one-hour lifetime and scope checks and optional `sub` delegation; `refresh_token`; `authorization_code` with PKCE); `GET /o/oauth2/v2/auth` (consent without a page, redirect with `code` and `state`); `POST /revoke`. Errors in the Entra and Google OAuth forms |
| Graph | `src/graph.ts` | Drive, item by id or `root` alias, item by path (`root:/a/b:` and `items/{id}:/rel:`), children with `$top` and `@odata.nextLink`, folder creation, PATCH (rename, move, description), DELETE, versions (newest first, `current`), version and item content through signed pre-authenticated download URLs, simple upload up to 4 MiB with creation of missing path folders, upload sessions (320 KiB fragments, in order, at most 60 MiB, no Authorization header, GET status, DELETE), asynchronous copy with a monitor URL, `$select`, conflict behaviours `fail`, `replace` and `rename` with the documented defaults |
| Drive | `src/drive.ts`, `src/fields.ts` | files get (with `alt=media`), list (`q` subset, corpora, `driveId`, paging), create metadata, PATCH (name, description, trashed, `addParents` and `removeParents`), DELETE, copy, revisions list, get and update (`keepForever`), shared drives get, `about`; uploads `media`, `multipart` and `resumable` (256 KiB chunks, 308 with `Range`, status query, cancel) for new files and new versions; partial responses with the `fields` parameter and the default field sets of the real API |
| Access rules | `src/auth.ts`, `src/state.ts`, `src/drive.ts` | Bearer tokens valid only on the API whose endpoint issued them, expiry and revocation, Drive scope check; drive rules: `forbidden` switch (403), `tenantId` and `allowedPrincipals`; a My Drive answers only its owner and the accounts in its `allowedPrincipals` (404 `notFound` for every call by id, left out of `files.list`) |
| State and fixtures | `src/state.ts`, `src/fixtures.ts` | In-memory drives, items, versions, credentials, tokens, codes, sessions and copy jobs; strict fixture format version 1 with every problem reported by path; folders from paths with ids derived from drive and path (stable across resets); declared hash values; merges all or nothing (ids checked first, then a dry run on a copy of the drives and items finds Graph name clashes and files standing in folder paths), so a rejected merge or `POST /_admin/items` leaves the state untouched; periodic purge of expired sessions, jobs, tokens and codes |
| Admin API | `src/admin.ts` | `health`, `reset` (optional new base document), `fixtures` (merge), `state`, `settings`, `credentials` (register, list without secrets), `oauth/codes`, `items` (create, inspect), the fault switches `items/{id}/move`, `/new-version`, `/delete`, `/purge-version`, `/corrupt-hash`, `drives/{id}/forbid`, `tokens/revoke`, `throttle`, `latency`, and the request log `requests` |
| Hashes and keys | `src/quickxor.ts`, `src/content.ts`, `src/certs.ts`, `src/client.ts`, `src/ids.ts`, `src/links.ts` | quickXorHash (Microsoft's algorithm, one XOR per input byte); SHA-256, MD5 and MIME types from names; self-signed RSA certificates encoded in DER without a dependency, thumbprints; client assertion builders for tests; id patterns and generators; signed download URLs and page tokens |
| CLI and self-test | `src/server.ts`, `src/self-test.ts` | `node dist/server.js --port 4310 [--host] [--fixtures <file or name>] [--public-url] [--verbose] [--self-test]`; `--fixtures demo` loads `fixtures/demo.json`; the self-test registers throwaway credentials and drives, then for both providers gets a token, lists a folder, uploads a file, checks the provider hash and lists again |
| Example fixtures | `fixtures/example.json` | The G.8 situations on a few files: a SharePoint file with a newer version than the pinned one and picker files, a disabled OneDrive (forbidden), a shared drive whose delegated refresh token is revoked, a Google Docs file and a binary file with revisions |
| Tests | `test/*.test.ts`, `test/fixtures/**` | 103 unit tests: quickXorHash (empty input, the 70 rclone vectors in one piece and in chunks, two 1 KiB vectors, agreement with a literal port of the C# reference on random input), token endpoints, every Graph and Drive call, every fault switch, the admin API, the fixture format, certificates, the self-test over real HTTP, and documented shapes (below) |

### Documented shapes

`test/shapes.test.ts` compares every response type with documented payloads stored in `test/fixtures` (its README names each source). Microsoft examples were copied unchanged from the public documentation repositories (microsoftgraph/microsoft-graph-docs-contrib and MicrosoftDocs/entra-docs): every field the mock sends must appear in the example with the same JSON type or be a property named in the resource's JSON representation, and every field of the example must be sent. Drive responses are checked against the `File`, `FileList`, `Revision`, `RevisionList`, `Drive`, `About` and `User` schemas of the official Drive v3 discovery document (revision 20260927, downloaded). The Google error and token examples were written out from the published guide examples because developers.google.com is blocked from this sandbox (see deviations).

## Review fixes

| Finding | Change | Test |
|---|---|---|
| `owners` of a My Drive file always named the drive owner | `renderFile` takes `owners` from the item's creator (`createdBy` of a fixture or `POST /_admin/items`, the uploading or copying principal), falling back to the drive owner when the creator has no email | `test/drive.test.ts` "names the account that created a My Drive file in owners" (BAGUS through `/_admin/items`, the owner's own upload, the fallback) |
| A rejected fixture merge could leave part of the document applied | `applyFixtures` checks ids, then applies the drives, folders and files to shallow copies of the drives and items (versions are skipped there) and touches the live state only when that passes; README, this note and the code comment say so | `test/admin.test.ts` "applies a merge all or nothing when the clash is in the folder tree" (Graph name clash, a file in a folder path, a folder description, `POST /_admin/items`) |
| Malformed percent-encoding in HTTP Basic client credentials gave 500 | `clientCredentials` answers 401 `invalid_client` | `test/identity.test.ts` refresh token case |
| A My Drive was hidden from `files.list` but readable by id for any Google principal | One visibility rule (`driveVisible`) for list and every call by id: the owner, or an account in `allowedPrincipals`; others get 404 `notFound` (the forbid switch still answers 403 first). The request log test now reads a shared drive file | `test/drive.test.ts` "shows a My Drive only to its owner and the accounts in allowedPrincipals" |
| `removeParents` and the file id of a resumable session URL were not checked against the D.5 pattern | `PATCH /drive/v3/files/{id}` checks the file id, `addParents` and `removeParents` before anything else; the resumable `PUT` and `DELETE` check `:fileId` before the session lookup | `test/drive.test.ts` "answers 400 for ids that fail the D.5 pattern" |

- WP-15: use the configured token URL as the assertion audience; send `x5t#S256`; do not send the bearer token to upload URLs; switch to an upload session above 4 MiB with 320 KiB fragments, and to resumable uploads with 256 KiB chunks for Drive; always pass `fields` and `supportsAllDrives=true`; read the creator of shared drive files from the first revision's `lastModifyingUser` and of My Drive files from `owners[].emailAddress`; a service account that should reach a My Drive needs to be in the drive's `allowedPrincipals`, or must act as the owner (the owner's refresh token, or `sub` delegation); Google Workspace files have no checksum or `headRevisionId` (use the revisions list); poll the copy monitor (`copyPendingPolls` setting, 1 by default); `GET /_admin/requests` shows token requests and the Authorization header use for the caching and egress tests. `tools/mock-providers/src/**` is listed in WP-15's paths for missing extensions.
- WP-13: `POST /_admin/oauth/codes` gives a code for `credentials/oauth-exchange` tests; the consent page at `/o/oauth2/v2/auth` follows `login_hint`.
- WP-18 (`deploy/docker/mock-providers.Dockerfile`): copy `tools/mock-providers/dist` and `tools/mock-providers/fixtures`, and run `node tools/mock-providers/dist/server.js --port 4310 --fixtures demo` (host `0.0.0.0` by default).
