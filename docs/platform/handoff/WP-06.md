## Observations on the plan SQL (reported, not changed)

- `ref/0001` grants `SELECT, INSERT, UPDATE ON ALL TABLES IN SCHEMA ref` to `mscd_pack_installer` and `SELECT` to `mscd_app` after Kysely created `ref.kysely_migration` and `ref.kysely_migration_lock`, so the pack installer may write those two bookkeeping tables. Harmless today; a later ref migration could revoke it.
- `assert_member` treats a membership with `status = 'disabled'` as a member (it checks `deleted_at` only). `MembershipService` (WP-39) must check the status; the trigger is a backstop.
- `assert_member` reads `platform.org_membership`, which has forced RLS: a write with a person column but without `app.org_id` (and without platform scope) is rejected as "not a member". Every tenant write sets `app.org_id` anyway (RLS), so this only matters for scripts.
- `platform.idempotency_key` has no platform scope by design (D-31): writes and reads must carry `app.org_id`, also in jobs.
- The Kysely Migrator uses one advisory lock for every schema, so `tenant create` waits while `migrate` runs, and the reverse.
