# WP-04 handoff: framework pack sources from the sample

## What was built

| File | Content |
|---|---|
| `packs/scripts/extract-from-sample.mjs` | Imports `apps/web/src/data/mscd-data.js` and writes the six pack source folders of G.7 in the E.8 layout. Deterministic output; `--check` regenerates in memory and exits 1 on any file that differs, is missing or is not produced by the script; `--help`; an unknown option exits 2. Write mode rewrites only changed files and removes files it no longer produces. Neither mode follows a symbolic link: a link, or any entry under `packs/sources` that is neither a regular file nor a folder, stops the script before anything is written or removed, `packs/sources` itself must be a real folder in the repository, and every file or empty folder it removes is checked by real path to be inside `packs/sources`. The pack set of D-14 is a table in the script and is checked against the sample's `PACKS` and `MS` records (version, edition, beta flag, withdrawn and transition editions, framework code), so a change on either side stops the script with a message |
| `packs/scripts/validate-sources.mjs` | Checks every pack folder: required files and no others (apart from `mappings/*.csv`), UTF-8 without BOM, LF, final newline, CSV headers of E.8 and field counts, JSON pretty-printing, manifest fields and semantic versions, `pack_id` equal to the folder and to `<framework_code>-<edition>`, `catalogue` consistent with `catalogue.csv`, no `datasets`, value types and `ref` column lengths of C.5, unique codes, references (catalogue and finding conditions to requirement codes where given, frequencies, chain entity types in the C.10 record tables, risk profiles of risk stages, document template types, drift rule stages), contiguous chain positions, phases and activities, the lookup domains `doc_type` and `treatment_option`, matching label keys in both languages with a theme label per catalogue theme. Prints the counts per pack; `--dir` validates another folder |
| `packs/scripts/lib/pack-format.mjs` | The file list, CSV headers, allowed values, RFC 4180 writer and parser, JSON writer and clause code ordering shared by both scripts |
| `packs/sources/<pack_id>/` | 18 files per pack, 108 in all, generated by the script |
| `packs/README.md` | Commands, pack table, the short-titles rule with the six ISO 27001 audit activities and six finding conditions, the file format and every derivation rule |

Checked beyond the acceptance commands:

- The validator reports injected faults by file and line: an unknown catalogue requirement code, an unknown chain entity type, a phase number gap, a missing lookup domain, an unknown drift kind, a missing final newline, a missing and an extra file, an unknown finding classification and requirement, a manifest with `datasets` and a non-semantic version, a duplicate requirement code and carriage returns (16 faults, 16 errors, exit 1).
- `--check` reports a changed file, a missing file, an extra file and an extra pack folder (exit 1); write mode then repairs all four and `--check` passes.
- In a scratch copy, both modes exit 1 without writing or removing anything when `packs/sources` holds a symbolic link to a folder outside the repository, a relative link to `apps/web/src`, a generated file replaced by a link to an outside file, a dangling link or a FIFO, and when `packs/sources` itself is a link; the link targets were left untouched. An extra regular file, an extra pack folder and empty folders are still removed, and a missing `packs/sources` is recreated.
- Python's `csv` module reads all 72 CSV files (885 rows) with the expected field counts; all 36 JSON files parse.
- Catalogue item codes, themes and order equal `buildReqs(isms)`; activity counts equal `PHASES` for every system; activity output codes use the sample's own `OUTPUT_MAP` rule, so they equal the `out` values the sample shows.
