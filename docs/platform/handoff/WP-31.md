# WP-31 handoff: Full-stack smoke test

## What was built

| File | Content |
|---|---|
| `tools/smoke/run-smoke.mjs` | The runner behind `npm run test:smoke` (J.9). Builds `cyberlentera/mscd-server-demo` (target `demo`), `cyberlentera/mscd-web` and `cyberlentera/mscd-mock-providers`, tag `smoke` or `MSCD_VERSION`, with `docker buildx build --load --secret id=build_ca,src=<CA>` (R-12: `--build-ca`, else `$MSCD_BUILD_CA`, else an empty temporary file); `SMOKE_SKIP_BUILD=1` uses existing images and stops with exit 2 when one is missing. Removes a leftover stack of its own project, checks the four published ports, chooses the internal network (`172.31.250.0/24`, or the first free `172.31.x.0/24` when another Docker network already uses it, or `MSCD_SUBNET` and `MSCD_WEB_ADDRESS`), runs `docker compose -p mscd-smoke -f deploy/compose/docker-compose.yml -f deploy/compose/docker-compose.demo.yml up -d --wait`, then `playwright test` with the suite's configuration. After a failure it prints the logs of unhealthy services and saves all service logs to `test-results/compose.log`. `docker compose down -v --remove-orphans` runs on success, on failure and on SIGINT or SIGTERM (exit 130). `--keep` or `SMOKE_KEEP=1` leaves the stack running, `--down` removes it, arguments after `--` go to Playwright. Exit codes 0, 1 (build, stack or test failure), 2 (usage or missing requirement) |
| `tools/smoke/playwright.config.mjs` | One worker, no retries, Chromium of Playwright 1.56.1 (revision 1194) with `--host-resolver-rules=MAP keycloak 127.0.0.1:<MSCD_KEYCLOAK_PORT>`, list and HTML reporters, traces and screenshots on failure, output under `SMOKE_OUTPUT_DIR` (default `tools/smoke/test-results`) |
| `tools/smoke/tests/smoke.spec.mjs` | The J.9 journey in one serial browser session (11 steps): stack answers through the web image (`/healthz`, profile in demo mode, Keycloak provider, Mailpit API); `rina` signs in with password and TOTP; portfolio shows the four systems; ISMS controls show the UI 4.7 counts (61 of 93, 18, 4, 14 of 22, 5); `A.5.13` marked complete with its toast and new status; `EV-0124` re-linked to `Access-Review-Q3-2026.xlsx` from the mock SharePoint picker and gone from "File cannot be verified"; a generated file uploaded to `EQ-0154` (QMS Managed Vault) and its SHA-256 compared with the hash the test computed; integrity check started with its toast; a reminder for `A.5.1` found in Mailpit (`[MSCD] Reminder ...` to Rina, polled for up to 90 s); `bagus` signs in through the Keycloak login form and the local TOTP step; sign out returns to `/login` and `GET /me` answers 401. Page errors and 5xx answers during the journey fail the last step |
| `tools/smoke/lib/totp.mjs` | The TOTP logic copied from `tools/scripts/demo-totp.mjs` (G.3 secret rule, RFC 6238), plus a check against the RFC 6238 vectors that the runner calls before it starts |
| `tools/smoke/lib/settings.mjs` | Ports and URLs from the Compose variables `MSCD_HTTP_PORT`, `MSCD_HTTPS_PORT`, `MSCD_KEYCLOAK_PORT`, `MSCD_MAILPIT_PORT` (defaults 18080, 18443, 18088, 18025), shared by the runner and the Playwright configuration |
| `tools/smoke/package.json` | Script `smoke` now runs `node run-smoke.mjs` (no dependency change) |
| `tools/smoke/README.md` | What the test does, how to run it, every setting, exit codes, how to read a failure |

## Acceptance

Run from the repository root with Docker 29.6.2 and Compose 5.3.1. As the orchestrator asked, the published ports were moved off the orchestrator's stack (project `mscd-m1` on 18080, 18443, 18088, 18025) with `MSCD_HTTP_PORT=28080 MSCD_HTTPS_PORT=28443 MSCD_KEYCLOAK_PORT=28088 MSCD_MAILPIT_PORT=28025`; the project was the default `mscd-smoke`.

## Findings for other work packages

1. Picker modal without a scroll area (WP-25 web integration with WP-14 fixtures). In the API stack `GET /storage/repositories/sp/browse?...&path=Evidence/2026/Q3` returns 82 files because `tools/mock-providers/fixtures/demo.json` places every ISMS evidence file in `Evidence/2026/Q3`. The generated `Modals.jsx` gives the file list no maximum height, so the modal (fixed, centred) grows past the window on both sides. A real user with a mouse cannot pick a file or press "Link selected file". Suggested fixes: put the filler evidence files of the fixture in the quarter folder of their date (the sample shows three files in Q3), and cap the picker list in the controller or give the list a scroll area through the mockup and `gen:views`. When fixed, the smoke test clicks with the mouse again and stops printing the layout line.
