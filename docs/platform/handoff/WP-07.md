# WP-07 handoff: web DataSource seam (sample mode)

## What was built

The web controller no longer derives records itself and no longer keeps an override store. It loads a snapshot from a `DataSource` (BUILD-PLAN H.2), reads one precomputed bundle per system, and sends every action that changed data to the source as a command, then reloads the systems the command changed. The sample source reproduces the former behaviour exactly; the sample E2E suite passes without edits.

Controller changes in `MscdApp.jsx`:

- `componentDidMount` uses `props.dataSource` or awaits `createDataSource()`, then `ds.load(state.org)`. `state.D` is the snapshot merged with `T`, `TERA`, `INTEG`, the `LOC` visuals (added only where an entry has no colour or icon) and `makeDates(snapshot.today)`; `state.snap` keeps the snapshot as the source returned it. Until it arrives `render()` returns a loading panel (`.mscd` element with the theme, density and font attributes, background `var(--bg)`, text "Loading MSCD" or "Memuat MSCD", `role="status"`), which has no `main h1`, so the E2E helper `openApp` still waits for the app.
- `ORGS` reads `D.orgs`. `setOrg`, the persona menu (`setRole`) and every command apply the new snapshot and the follow-up state (state reset, closed modal, toast) in one update.
- `data(ms)` returns the bundle of the system; `chain(d)` and `gateItems(d)` return the bundle lists with `li()` applied to `title`, `act`, `type` and `why`, cached per list and language; `phases(d)` returns the bundle phases; `findX`, `titleOf` and the current phase come from `sample-derive.js`. `state.ov`, `ovSet` and `newEvidence` are gone.
- Commands through `command(run, done)`: `markComplete` (requirement, activity, My Tasks), `verify` (verify modal), `assign` (reassign modal), `startReview` (document drawer, My Tasks), `completeRecordAction` (My Tasks record), `linkFile` (picker modal), `uploadFile` (vault modal). A result with `ok: false` closes the modal and shows `li(error.message)`; a rejected promise shows "Connection lost. Try again."
- `openPicker` tests the repository kind `D.LOC[ms.loc][1]`; `modalVals` and `modalOk` read `m.listing ?? D.PICKER_FILES[m.src]`, and `modalOk` passes `listing.refs[i]` as `file.ref` when the listing has refs.
- Fallbacks of step 11, each with the former literal: `ms.gateName`, `ms.gtSuggestions`, `doc.approver`, `doc.path`, `doc.hashAlg`, `e.hash` (shown as its first 10 characters, `...` and its last 4, which gives the former `<code letters>a91f...3c7e`), `e.lastGoodCheck` (its date) and `e.lastCheck`, `ms.banner.kind` for the portfolio attention item, `PACKS[ms].status`, `REPOS[].actions` and `REPOS[].adapter`, `ms.audit.prepWindowDays`.

## Follow-ups

- WP-14 (export script): `SampleDataSource.load('<org>')` is per organisation (deviation 3); replace `ChainItem.ref` and `Activity.doc` objects by keys; read the `literals` of G.2 from `MS[].gateName` (pair), `MS[].gtSuggestions` and `MS[].approver`. The bundles hold pairs for the fields of deviation 1. - WP-25: the API branch of `createDataSource.js`; H.5 steps 5, 6, 8, 10, 12, 13 and 14. `command()` already shows `li(error.message)` for `ok: false` and "Connection lost.
