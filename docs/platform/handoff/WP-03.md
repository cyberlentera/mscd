### ESLint rules (F.10)

`no-restricted-syntax` guards the injected pool everywhere in `apps/server/src` except `src/db`, `src/modules/tenancy` and `src/seed`: every reference to `this.db` (so method calls at any depth of a builder chain such as `this.db.withSchema(...).selectFrom(...)`, `this.db.transaction()`, `this.db.connection()` and `this.db.mergeInto(...)`, passing it as in `.execute(this.db)`, and aliases such as `const k = this.db` or `const { db } = this`); for a binding named `db`, a method call on it or on one of its members (`db.selectFrom(...)`, `db.schema.createTable(...)`), passing it to a call or a constructor (`.execute(db)`), and aliasing it; and a method call on any other `x.db` member. Outside `src/modules/{identity,ops,jobs,audit,packs,license,tenancy}`, `src/cli`, `src/seed` and `src/worker` it flags every reference to a member `withPlatform` (so a direct call, `.call`, `.apply`, `.bind`, `x['withPlatform']` and aliases such as `const w = x.withPlatform`), a call of a free function `withPlatform(...)`, importing it, destructuring it (`const { withPlatform } = x`, also with a quoted key or a new name), and passing or aliasing the bare name; a type that only declares `withPlatform` is not flagged. The local rule `mscd/no-session-settings` removes SQL comments (`--` and `/* */`, outside quotes) from every string and template literal, then flags each `SET` followed by white space that starts a statement unless the next word is `LOCAL`, `TRANSACTION` or `CONSTRAINTS`. A statement starts at the start of the string, after `;`, after the PL/pgSQL words `BEGIN`, `THEN`, `ELSE` and `LOOP`, after a dollar-quote opener (`$$`, `$tag$`) and after an opening single quote, which covers dynamic SQL in `EXECUTE '...'` and the first argument of `format(...)` (a closing dollar quote or single quote does not start one, so the `SET` option of `CREATE FUNCTION` after its body passes). This covers `SET SCHEMA`, `SET SESSION ...`, `SET NAMES`, `SET ROLE`, `SET name = v`, `SET name TO v` and a bare `'SET '` joined to the rest. `SET` in capitals always counts; any other spelling (lower or mixed case) counts only in a SQL statement shape or as a bare `'set '` with nothing after it in the literal, so English messages such as "Set either A or B", "Begin set up of the organisation" or "The password is missing; set a new one" pass, while "set it to 5" does not. It also flags `set_config(...)` unless its third argument is a true literal (`true`, `'on'`, `'t'` and the like), so `false`, `'off'`, a placeholder and a call not closed in the same literal are errors. `test/unit/lint/tenant-scoping-rules.test.ts` proves each case through the ESLint API. TypeScript files use `@eslint/js` and `typescript-eslint` recommended; `.mjs`, `.cjs` and `.js` files outside `apps/web` use `@eslint/js` recommended with Node globals; the web JavaScript, `project/`, `chats/`, `packs/sources`, every `dist` and `apps/server/src/generated` are ignored.
