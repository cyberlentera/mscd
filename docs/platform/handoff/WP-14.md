## Deviations

- Through the gateway key service the Google Drive credential is sealed with the OAuth client only, without the expired delegated refresh token, because the gateway seals refresh tokens only inside the consent flow. The in-process key service (tests) seals the token too. Both give the sample's `verification_pending` state, since the mock answers `invalid_grant`.
- `npm run seed:demo` runs `apps/server/scripts/seed-demo.mjs` (created by WP-04, outside WP-14 paths), which already calls `ensure-built.mjs`, then bootstrap (when `MSCD_DATABASE_ADMIN_URL` is set), migrate and `seed demo`.
- Memberships and role assignments are written to the C.6 tables directly, as instructed, so the seed does not depend on WP-39 services.
- G.3 names the OIDC provider `keycloak` for both `ndt` and `tst`, but `identity_provider_slug_uq` is unique across organisations (C.4), so the seed creates `keycloak` for `ndt` and `keycloak-tst` for `tst` (`seed-demo.ts`, tested in `seed-command.test.ts`). Sign-in to `tst` through Keycloak uses `/auth/oidc/keycloak-tst/...`. Orchestrator: please amend G.3 to match, so WP-27, WP-31 and SSO tests use the right slug.
