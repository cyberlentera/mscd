## Incident

`uninstall.sh --purge` (WP-28) removes every tag of `cyberlentera/mscd-web` and `cyberlentera/mscd-server`, not only the installed version. The first acceptance run therefore also deleted `cyberlentera/mscd-web:m1`, `:smoke`, `:wp28` and `:wp31`. They were rebuilt at once from the current sources (`web.Dockerfile`, default API mode) and tagged again; their content is the current web build, not the original one. The second run protected the tags with temporary `wp-33-keep/...` tags and restored them.

## Follow-ups

- WP-28 owner (`deploy/scripts/uninstall.sh`): `--purge` should remove only the MSCD image tags of this installation (the version in `.env` and the versions saved in `backups/`), not every tag of the repositories.
- WP-28 owner (`install.sh`): either accept a default organisation with `--yes` or the plan's acceptance of WP-33 should pass `--org-slug` and `--org-name`.
- Plan owner: WP-33 acceptance should use a version at least the packs' `engine_min_version` (for example `1.0.1-wp33`), or the packs' minimum should be lowered.
- Server (any later WP): a command to grant `platform_operator` (for example `admin create-user --platform-operator`) and an `mscd-server diagnostics` command that writes the archive of `POST /ops/diagnostics` without a session; the guide can then drop the support step.
- Helm chart (WP-29 owner): a one-shot Job or documented values for `tenant create` and `admin create-user`.
- WP-11 note: `apps/server/src/modules/identity/common-passwords.txt` carries the SecLists notice in its header; a third-party notices file in the bundle is still open.
- `docs/DEVELOPMENT.md` (WP-25 owner) line 280 still says the web default is `sample` and that release bundles always pass `APK_UPGRADE=true`; with this build script a release passes `true` through `--release` (or `--os-updates true`), and a test build uses `auto`.
