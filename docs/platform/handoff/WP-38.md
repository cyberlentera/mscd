# WP-38 handoff: web auth pages and boot router

## What was built

The API build of the web app (`VITE_DATA_SOURCE=api`) now boots through a sign-in layer: system profile, session check, then the sign-in and account pages or the application. The sample build boots exactly as before and never loads the new code (the auth chunk is not even emitted in the sample build).

| File | Content |
|---|---|
| `apps/web/src/data/api/ApiClient.ts` | `ApiClient` of H.4: `fetch` with `credentials: 'same-origin'`, JSON bodies (raw `Blob`, `FormData`, `ArrayBuffer`, `URLSearchParams` and streams pass through), `Accept-Language` (`setLanguage`), `X-CSRF-Token` on every non-GET request. The token is taken from every successful answer that carries `csrfToken` (`Me`, `LoginResponse`) or `me.csrfToken` (`MfaEnrolConfirmResponse`), so session rotations (sign-in steps, organisation and persona switch) need no extra code; `rememberMe(me)` and `setCsrfToken` set it explicitly. Errors never throw: a problem becomes `ApiError {status, slug, rule, message: [messages.en, messages.id] or [title, title], messageKey, detail, methods, retryAfter (body or Retry-After), errors, requestId}`, any other error body a generic text, a network failure status 0 with "Connection lost. Try again." (`Koneksi terputus. Coba lagi.`). Events: `onUnauthenticated` (a 401 of a request made with a session), `onReauthRequired` (409 `reauth-required`, with the methods and the `org` of the request body), `onSignedOut` (a successful `POST /auth/logout`, or its 401). `call(route, {params, query, body})` takes a shared `RouteDef` (path parameters URL-encoded); a 401 of a route whose auth level is a sign-in step (`public`, `mfa_pending`, `enrolment`, `guest_otp`) does not notify. `get`, `post`, `put`, `patch`, `request`, `logout`; helpers `toApiError`, `buildPath`, `buildQuery`, `parseRetryAfter`, `problemSlug`, `csrfTokenIn` |

## Follow-ups

- WP-25: build `ApiDataSource` on `options.client` (the `ApiClient` the boot passes to `createDataSource`), so the 401, `reauth-required` and sign-out events reach the boot; `logout()` can call `client.logout()` (the boot shows the sign-in page on `onSignedOut`); call `client.setLanguage(lang)` when the controller language changes; `onUnauthenticated` may delegate to `client.onUnauthenticated`. Shared `RouteDef`s can be called with `client.call(route, {params, query, body})`; `ApiError` already has the `CommandResult.error` shape. The API bundle still holds the `SampleDataSource` chunk until the API branch of `createDataSource.js` replaces the sample import (WP-25 acceptance greps for it).
- WP-16: after a callback that continues with the local TOTP step, redirect to `/login/mfa#csrf=<token>` (or `/login/enrol#csrf=<token>` without a factor), the token being `csrfTokenFor(<new session cookie>)` of WP-11; errors to `/login?error=<code>`; the sign-in page passes `returnTo` (a relative path) and the invitation page `invitation` to the start routes.
- WP-39: `GET /me` must answer 401 without an active session (the boot treats any other error as a start failure); today the route is not mounted (404).
- WP-26: the guest page posts `{token}` to `/auth/guest/start` and `{email}` to `/auth/guest/login`, then `{code}` to `/auth/guest/verify`, and continues with the `LoginResponse` status.
- WP-18: the `mscd-web` image must be built with `VITE_DATA_SOURCE=api` (absolute asset URLs). The QR code is inline SVG, so the CSP needs no `data:` image for it.
- WP-27: stable selectors: `#au-email`, `#au-password`, `input[name=remember]`, `#au-code`, `#au-recovery`, `#au-confirm`, `[data-testid=enrol-secret]` (the secret, grouped by four with spaces), `input[name=saved]`, `#au-new-password`, `#au-repeat-password`, `#au-guest-email`, `#au-guest-code`, `a[data-provider=<slug>]`, `.au-alert-error`, `.au-alert-ok`, `.au-alert-info`. The sixth digit submits the code fields.
- Orchestrator (outside WP-38 paths): `apps/web/README.md` could name `src/auth` and `src/data/api/ApiClient.ts`; `docs/DEVELOPMENT.md` (WP-25 in wave 10) could describe `VITE_API_TARGET`.
