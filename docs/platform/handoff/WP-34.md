WP-22 verifier finding (outbox relay could be blocked by rows that keep failing), fixed in `bullmq-job-queue.ts`:

- Permanent failure (a job name this build does not know, for example after a rollback): the row is parked at once (`attempts = OUTBOX_PARKED_ATTEMPTS`, 32767, the largest `smallint`; a transiently failing row stops counting at 32766) and logged once at error level (`event: job_outbox.stuck`, `parked: true`, row id, queue, last error). The relay never takes it again. Parked rows stay (cleanup removes relayed rows only).
- Transient failure (a Valkey error such as OOM, READONLY after a failover or NOAUTH after a password rotation): the row is never parked. It is retried with the backoff below, at most every 600 seconds, for as long as the outage lasts, and is relayed as soon as Valkey recovers. When it reaches `OUTBOX_STUCK_ATTEMPTS` (12, about 37 minutes of failures) it is logged once at error level (`event: job_outbox.stuck`, `parked: false`).
- Reset of parked rows once the cause is fixed: `UPDATE platform.job_outbox SET attempts = 0, run_at = now() WHERE dispatched_at IS NULL AND attempts >= 12` (resetting `run_at` too avoids a delay of up to 600 seconds left by the last backoff).
- Backoff: after a failure `run_at` moves to `greatest(run_at, now() + outboxBackoffSeconds(attempts))` (2, 4, 8 ... seconds, at most 600), and rows with attempts are taken only when `run_at <= now()`. A delayed job is never moved earlier. Rows are still taken by fewest attempts first, so new rows go first.
- `countStuckOutboxRows(trx)` counts rows with 12 or more attempts (stuck or parked) and feeds `mscd_job_outbox_stuck_rows` and the `job-outbox` health component.

## Plan findings

- F.12 logging: the pino redaction paths `*.password`, `*.secret`, `*.token`, `*.code` and the others match one level below the root only. A log call with a secret at the top level of its object (`logger.warn({ password })`, which nestjs-pino logs as a top-level member) is written to stdout unredacted. The diagnostics archive removes such values (scrubber), stdout does not. `apps/server/src/modules/platform/logging.ts` (WP-03 and WP-08) should add the bare paths (`password`, `secret`, `clientSecret`, `refreshToken`, `sealedBlob`, `privateKeyPem`, `certificatePem`, `token`, `code`) to `LOG_REDACT_PATHS`.
- Tenant migration state is not visible to the api. If the operator view should list it, the tenant secure function (WP-06 migrations) could grant `SELECT` on `<org>.kysely_migration` to `mscd_app`; `OpsService.migrations` would then list each readable tenant schema with one more entry in its schema list.
