# WP-27 handoff: web E2E against the API

## What was built

The specs of `apps/web/e2e` now run in two Playwright projects: the sample project as before (port 4173, parallel) and an API project that runs the same specs against a seeded api, one test at a time, with the api reset before every test. Tests that assert behaviour the api changes on purpose carry `@sample-only`; new `@api-only` specs cover sign-in, enrolment, sign-out, session end, guest access and the commands that differ.

## Follow-ups

1. Web controller owner (WP-25, `src/data/sample-derive.js` of WP-07): an external auditor's app crashes on landing. `overviewPhase(phs)` reads `.no` of the last phase, and the G.5 projection returns `phases: []`, so `overviewScreen` throws "Cannot read properties of undefined (reading 'no')" and the page goes blank. `apps/web/e2e/api-only/guest.spec.js` records the crash as an `issue` annotation; once fixed, the same step asserts `ui.title(gp)` without a change to the spec (the known-crash branch can then be removed).
2. Defect, not a decision. Owner of the demo seed (WP-14) or of the command (WP-20): `POST /ms/{ms}/phases/{n}/verify` answers "Phase 1 verified" for ISMS phase 1, which the seed holds as verified, where D.3 answers "Phase n is already verified" when there is nothing to do. `verifyPhase` decides by a `phase.verified` audit entry newer than the last activity change, and the seed writes no such entry for the phases it seeds as verified. Fix: the seed writes a `phase.verified` entry for each fully verified phase. The test "Verify phase on a phase that is already verified says so" in `phases.spec.js` is `test.fixme` in the API project until then.
3. Docs owner of `docs/DEVELOPMENT.md`: a section for the API E2E project. Suggested text: "`npm run test:e2e:api` builds the server, the mock providers and the web app in API mode, starts PostgreSQL, SeaweedFS and Mailpit containers and the api on 4174 and 3174, and runs the specs of `apps/web/e2e` against the demo seed, one at a time with a database reset before each test. It needs Docker and the ports 4174, 3174, 4310 and 4311. Tests tagged `@sample-only` run only in the sample project, `@api-only` specs only in the API project."
