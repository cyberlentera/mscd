# WP-24 handoff: notifications and exports

## What was built

| Area | Files | Content |
|---|---|---|
| Notification routes | `apps/server/src/modules/notifications/notifications.{controller,service}.ts` | `GET /notifications?unread=` (the session user's rows only, newest first, paginated, `ms` slug and a valid `ref` when stored) and `POST /notifications/{id}/read` (204; 404 for anyone but the recipient; the first read time is kept) |
| Email delivery | `notification-delivery.service.ts`, `notification-mail.ts`, `notification-mailer.ts` | E.6 through Nodemailer over `mail.smtp` (file and URL access disabled, timeouts): subject `[MSCD] <title>`, plain text and simple HTML, the recipient's `lang` preference (default English), a link under `http.public_url` (the app, or the download URL for `export_ready`), header `X-MSCD-Mail: notification:<kind>` or `notification:digest`. Each row is locked with `FOR UPDATE SKIP LOCKED` while it is sent; a failure increments `email_attempts` and keeps `last_error`; the fifth failure sets `failed`; rows of recipients who are no longer active members (or have no address) become `skipped` |
| Jobs | `notification.jobs.ts`, `document-review-alerts.service.ts` | `notifications.dispatch` (named rows, every pending row of the organisation, or every active organisation for the WP-22 sweep with `orgId: null`; a run for named rows throws while a row may still be retried, so the queue retries with backoff), `notifications.digest` (one email per user with the pending digest rows created before the start of the organisation's current local day), `documents.review-alerts` (approved documents whose `next_review_at` is 60, 30, 14 or 7 days after today: `document_review_due` to the owner, digest for 60 and 30; once per document, tier and review date) |

A finished task is left alone |

## Deviations and decisions

| # | Item | Plan | Built | Reason |
|---|---|---|---|---|
| 1 | Scope of `notifications.dispatch` | Tenant jobs run in `withTenant` | The handler is declared `installation` scope so the worker accepts the WP-22 sweep envelope (`orgId: null`); all work is done per organisation in `withTenant`. The list of active organisation ids is read with `withPlatform` (one `eslint-disable-next-line` with its reason) | The worker refuses tenant jobs without an organisation (WP-22 deviation 6) |
| 2 | Content type of export downloads | The gateway's detection | The type of the format the server generated (`application/pdf`, the XLSX type, `text/csv`); the detected type is still stored on the `storage_object` | The gateway detects CSV as `text/plain`; F.13 allows the server's own type for generated files, and no client declaration is involved |
| 3 | Review alert idempotency | Not specified | Once per document, tier and review date, by the notification title that names both | `notification` has no column for the tier; a changed review date gets fresh alerts |
| 4 | Digest cut-off | "previous day's" | Pending digest rows created before the start of the organisation's current local day (real time), so a failed digest's rows go out the next day | `created_at` is database time; the fixed demo date must not hold rows back |
| 5 | Formats per export type | Not listed for every type | Portfolio board and readiness: PDF; SoA and document register: XLSX or CSV; audit trail: CSV; anything else 400 `validation` on `format` | D.3 and UI 3.6 name only these |
| 6 | Portfolio board systems | "permission rule of D.3" | The route needs `export.run` in any system (guard); the board has one page per system in which the requester holds `export.run` | A system without the permission must not leak through the organisation-wide export |
| 7 | Readiness "blockers" | Not defined | Blocked activities (with the gate item that blocks them) and blocked controls (with their note) | The two kinds of blocked records of the read model |
| 8 | Calendar fetch audit | F.13: every file response is audited | `file.downloaded` per fetch, actor the token's user, entity `calendar_feed_token` | The route is public; the token names the user |
| 9 | Calendar token format | Hashed token | Organisation prefix plus 32 random bytes, MAC stored | The public fetch must find one tenant schema without searching all of them (same pattern as the guest link of WP-26) |
| 10 | Export vault cleanup | WP-22 deviation 18 left removing the vault object to WP-24 | Not done: expired files are refused at download (404) and soft-deleted by `cleanup.expired`; the vault objects stay | D.5 has no delete operation on the gateway |
| 11 | Notification email link | "a link to the app" | `http.public_url` root, and the download URL for `export_ready` | The web app has no notification route yet |
